# Workflow

## Start of task

Every agent follows the consultation skill. It reads the entrypoint, catalog, relevant canonical guidance, and source. At the first knowledge access of a new UTC date, the daily candidate review runs before implementation.

## During task

Capture a reusable, evidenced observation as its own candidate file. Avoid editing shared indexes unless needed; re-read the latest file immediately before a small append or change. Candidates are proposals, not instructions.

## End of task

Update canonical knowledge only when authorized and supported by evidence. Include source links and validity scope. Leave a concise task handoff when work spans agents or worktrees.

## Promote

A maintainer reviews the candidate, approves its destination, updates canonical docs and catalog, and marks the candidate promoted in the same Git change. The MCP stays read-only.

# Fluxo de trabalho

## Início da tarefa

Todo agente segue a skill de consulta. Ele lê as instruções de entrada do projeto, o catálogo, as orientações relevantes e as fontes. No primeiro acesso ao conhecimento em uma nova data UTC, a revisão diária dos candidatos acontece antes da implementação.

## Durante a tarefa

Registre observações reutilizáveis e comprovadas em arquivos candidatos separados. Evite editar índices compartilhados quando não for necessário; releia o arquivo mais recente imediatamente antes de um acréscimo ou edição pequena. Candidatos são propostas, não instruções.

## Fim da tarefa

Atualize conhecimento canônico somente quando houver autorização e evidência. Inclua fontes e escopo de validade. Deixe um handoff conciso quando o trabalho envolver outros agentes ou worktrees.

## Promoção

Um mantenedor revisa o candidato, aprova seu destino, atualiza os documentos canônicos e o catálogo, e marca o candidato como promovido na mesma mudança Git. O MCP permanece somente leitura.
