# Contributing

Issues and pull requests are welcome. Keep changes focused and preserve the project's core guarantees: Git remains the source of truth, MCP knowledge access stays read-only, responses cite sources, and approval is required before promotion.

Before proposing a change:

1. Read the relevant protocol and architecture docs.
2. Open an issue for changes to knowledge lifecycle, MCP surface, or installed project layout.
3. Include rationale, user impact, migration notes, and verification steps.
4. Never include secrets, private project knowledge, or customer data in examples or issues.

By contributing, you agree that your contributions are provided under the MIT License.

# Contribuição

Issues e pull requests são bem-vindos. Mantenha as mudanças focadas e preserve as garantias centrais do projeto: Git continua sendo a fonte da verdade, o acesso ao conhecimento pelo MCP é somente leitura, as respostas citam suas fontes e a promoção exige aprovação.

Antes de propor uma mudança:

1. Leia os protocolos e documentos de arquitetura relevantes.
2. Abra uma issue para mudanças no ciclo de conhecimento, na superfície MCP ou no layout instalado nos projetos.
3. Inclua a justificativa, o impacto para usuários, notas de migração e como validar.
4. Nunca inclua segredos, conhecimento privado de projetos ou dados de clientes em exemplos ou issues.

Ao contribuir, você concorda que suas contribuições são fornecidas sob a licença MIT.
